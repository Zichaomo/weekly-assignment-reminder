# 每周作业提醒（北化在线）

抓取北京化工大学「北化在线」THEOL 平台的课程作业和在线测试，合并手动补录的任务，在本地控制台查看、预览和发布提醒，并支持 Windows 每周定时推送。

提醒面向全班，以截止日期筛选，**不按本人是否提交过滤**。控制台检索默认扫描未被拉黑的全部课程，不依赖平台首页「待提交作业」视图，避免本人提交后整门课从首页消失而漏提醒。

文档入口为本页的部署和日常使用说明、[开发维护](docs/开发维护.md)、[验收记录](docs/验收记录.md) 及 [登录与部署优化](docs/登录与部署优化.md)。本机代理执行约定保存在本地 AGENTS.md。

## 首次部署

1. 准备 Windows 和 Microsoft Edge。安装 Python 3.14，安装目录选择 `%LOCALAPPDATA%\Programs\Python\Python314\`，与项目启动器默认路径一致。安装包可从官方 Windows 下载页获取。[Python Windows 下载页](https://www.python.org/downloads/windows/)
2. 双击项目根目录的 `setup.bat`。它会为该 Python 安装 Playwright 和 Pillow，然后打开控制台。首次安装依赖需要网络。项目复用系统 Edge。
3. 新部署首次打开时会显示「首次部署与使用指引」。也可随时从「管理 → 部署指引」打开，查看解释器、依赖、Edge 和课程初始化状态。
4. 在「管理 → 学校账号」录入账号密码，或点击「导入 Edge 已存凭据」。保存后点「重新登录」，在学校认证窗口中完成验证码，再用「检查登录状态」确认结果。
5. 在「管理 → 企微推送」选择提醒渠道，填写主用机器人地址。按需填写个人、测试和正式备用地址。可先使用「复制到剪贴板」或「仅生成本地文案」。
6. 回到部署指引点击「刷新课程表」，再通过课程管理设置三个名单，检索北化在线并查看两份推送预览。
7. 需要自动提醒时，从「管理 → 定时发布」设置每周日时间和提醒天数，后续补推检查包含在主任务中。

账号密码及企微链接均可在控制台管理，配置文件由保存操作自动创建。日常双击 `console.bat` 即可。使用其他 Python 安装目录时，也可用已安装依赖的解释器运行 `python data/server.py`，打开 `http://127.0.0.1:8277`。CLI 注册计划任务、网页定时设置和后台子进程跟随入口解释器。

### 学校账号与企微推送管理

「学校账号」管理单个学校账号。账号密码使用当前 Windows 用户的 DPAPI 加密后保存，登录与自动续登优先使用该凭据。已有 Edge 凭据通过显式导入转为控制台管理；读取不到时可直接录入。密码框留空保留同一账号的原密码，更换账号需要填写新密码。移除操作清除控制台保存的凭据。

每次保存账号会要求重新登录并使旧扫描失效，后续需要重新检索。更换已管理账号时自动建立新的缓存范围；首次录入另一个账号时勾选「这是另一个学校账号」。随后重新登录、刷新课程表和检索，并检查已有课程名单。

「企微推送」分别管理班级渠道、主用地址、测试地址、正式备用地址及个人完整提醒。主用地址用于日常控制台和定时发布，测试和正式备用地址供显式 CLI 选择使用。已保存地址显示配置状态，输入框留空保留原值，勾选清除删除该项。原有 PushPlus 和桌面微信配置可继续选择对应渠道使用。

设置保存有版本冲突检查，并在平台任务运行时暂停修改。修改地址后按实际目标参与既有去重和发送规则。配置文件、加密凭据和登录专用 `data/browser-profile/` 均属于本机私有状态，新电脑重新录入凭据并登录。

仓库不包含真实配置、登录会话、课程名单或缓存。不要把 `config.json`、`storage_state.json`、真实日志或课程材料发给别人；机器人 webhook 中的 key 可以用于向对应群发消息。

## 控制台日常使用

| 操作 | 行为 |
| --- | --- |
| 打开控制台、修改日期范围 | 读取本地 SQLite，不访问学校平台 |
| 检索北化在线 | 后台扫描课程列表，按任务展示进度；完成后按需补齐正文 |
| 含全部平台作业 | 列表包含已过期平台条目；推送仍按未来天数筛选 |
| 抓在线测试 | 控制本次扫描是否读取测试栏目 |
| 内容 / 刷新正文 | 优先读有效缓存，缺失或过期时可重新抓取 |
| 只重试课程 | 重扫指定课程，保留其他课程旧缓存 |
| 预览 | 使用本地快照生成两份文案，独立于平台抓取队列；可展示旧数据并说明发布阻断原因 |
| 提前发布 | 要求缓存完整、身份有效且足够新；条件不符时拒绝发送，先重新检索 |
| 手动添加 / 编辑 / 完成 / 删除 | 管理平台外的作业；完成后不再进入待办提醒 |

手动条目存于 `data/manual.json`；平台条目本身只读。「浏览器打开」按提交状态进入提交或结果页面，提交状态不参与班级提醒筛选。

`console.bat` 会先等服务可用再打开 Edge 应用窗口；已有窗口时置前复用。关闭窗口后，服务依据页面心跳与浏览器进程退出条件停止，可能有约 30 秒延迟；也可点击管理菜单（旧 Web 界面底部）的「停止控制台服务」。`console-legacy.bat` 保留旧版 WinForms 入口，但新增正文规则、后台更新和定时面板以 Web 控制台为准。

Web 默认入口已接入以 `ui_v0` 为基线的新界面，源码位于 `data/ui/`，保留原型原稿。图标使用本地 SVG，字体回退本机字体，无 CDN 依赖；窗口固定在视口内，列表与详情独立滚动。管理菜单提供三个名单、课程正文规则、定时与后台版本、运行记录及裁剪备份导出。原 Web 控制台保留在 `/legacy`。已有后台需重启后加载新入口。

管理菜单按「账号与推送」「课程与内容」「系统与维护」三栏排列，顶部部署指引采用固定底色、左对齐样式。窄窗口采用分组双列布局，低高度窗口可在菜单内滚动。

「管理 → 运行记录」显示后台正在进行和已结束的任务，每 1.5 秒刷新，支持展开过程、错误和课程覆盖，并分页加载更早记录。检索、正文、预览、发布及本地管理操作持久保存在 SQLite，刷新页面或重启后台后可继续查看。安装前的任务按已有台账恢复结果，逐条过程从安装后开始保存。

## 课程名单与提醒受众

| 名单 | 扫描范围 | 推送范围 |
| --- | --- | --- |
| 课程黑名单 | 整门课作业、测试均跳过 | 不进入提醒 |
| 测试黑名单 | 只跳过该课测试，作业照抓 | 保留该课作业 |
| 选修课名单 | 作业、测试照抓 | 不进入班级提醒，进入个人完整提醒 |

名单修改由用户执行，扫描不会自行把课程加入黑名单。选修课可按编号或名称片段添加，名称不唯一时需填写更具体的名称或编号。

- 班级提醒使用顶层 `channel` 与对应渠道配置，企业微信使用 `wecom_webhook`。
- 个人提醒为含选修课的完整清单，选修条目带标记。渠道配置见 `personal`；未配置可用个人渠道时不会回退到班级群。
- `wecom_webhook_test`、`wecom_webhook_prod` 仅在任务命令显式选择 `--wecom test`、`--wecom prod` 时使用；Web 定时设置跟随 `--wecom config`。
- `channel` 支持 `clipboard`、`wecom`、`pushplus`、`wechat`、`none`。微信桌面 UI 自动化受客户端版本影响，不建议作为默认通道。

## 正文与推送规则

操作栏「课程正文规则」可编辑或新增课程规则，支持名称精确匹配和前缀匹配。精确匹配优先；多个前缀匹配时采用名称最长的规则。

| 内置课程匹配           | 默认正文策略                       |
| ---------------- | ---------------------------- |
| 大学物理实验（前缀）       | 统一提示「详细要求见北化在线」              |
| 普通物理（前缀）         | 去除已知通用提交说明，保留其余文字要求          |
| 嵌入式系统创新应用与实践（精确） | 保留全部纯文字，只清理行边空白和空行           |
| 复变函数（前缀）         | 正文图片全部就绪时发送原图                |
| 未匹配课程            | 自动识别明确题号、章节、页码和任务；不确定时提示查看平台 |

还可将任意课程切换为上述五种策略。去套话和全文策略遇到图片、表格、附件时回到保守识别；原图策略无可用原图时也回到保守识别。正文缺失、过期、失败或身份失效时不引用旧正文。无法识别的正文不需要每天人工确认，标题、截止时间和平台提示仍会正常进入提醒。

每条课程规则可设置群消息正文显示 1–20 个非空行，默认 3 行。超出时追加「……（详情参见北化在线）」，完整正文仍保留。手动作业和在线测试不使用这套作业正文规则。

编辑后可用本账号的缓存作业或粘贴文字「预览当前草稿」，试用不访问平台、不发送消息、不保存试用正文。保存后后续预览和推送直接使用新规则，无需重新抓取。内置规则可恢复默认，自定义规则可删除；任务运行或排队时不能保存，多页面同时编辑有版本冲突保护。配置保存在本地 `data/course_rules.json`。

单条作业仍可通过「确认推送内容」人工确认正文、选择不推正文或恢复自动识别。确认结果绑定原文版本和账号身份；原文更新后失效，保存冲突会保留草稿。人工确认优先于文字/原图策略；「仅提示查看北化在线」策略始终生效。

完整正文支持段落、列表、表格、图片和附件入口。图片可查看原图，拖动框选、调整角柄并保存多个裁剪区域；可重新编辑或恢复本图原图。保存不立即发送，原图始终保留。裁剪绑定正文版本、账号及裁剪 revision，冲突时保留当前选区草稿；有效裁剪在后续图片提醒中替代该原图。图片发送仍受课程正文规则和人工确认优先级控制。

## 群消息与图片

提醒按截止时间排列，分为「近两天截止」和「本周稍后」，显示标题、截止、倒计时及来源标记。本人是否提交不会出现在群消息中。没有待交条目时生成无作业提示。

无裁剪时，企业微信图片优先通过 `markdown_v2` 混排在所属作业文字后，再接下一项。图片链接须来自平台、可匿名读取且与缓存原图字节一致；不可用时回退图片上传。有有效裁剪时使用本地生成的 PNG 上传，不使用原平台链接冒充裁剪图，也不引入外部图床。预览与发送共享图片清单，发送前校验账号、正文版本、裁剪 revision、文件哈希及通道限制。其他渠道发送文字并提示到平台查看图片。

图文混排的文字使用 Markdown 强制换行（行尾两空格），保持紧凑逐行显示；只在图片上下增加空行分段，原有标题与分组间距保留。排版后再计算消息字节上限。这个兼容处理只作用于 Markdown 混排消息，图片顺序和普通文本消息的格式保持原样。

同一受众和实际目标上的相同内容默认 300 秒内去重，配置为 `dedup_window_sec`。文字和图片部分单独记账，部分失败重试跳过已成功部分；全部成功才记整次成功。班级和个人受众分别处理，一条成功不会掩盖另一条失败。

## 缓存与并发

列表持久化到 `data/cache/homework.sqlite3`，图片位于 `data/cache/assets/`。扫描按课程提交，失败课程的旧数据保留供查看，但不能冒充本次完整扫描。分页、空结果、作业与测试覆盖、课程索引变化和账号身份都参与发布检查。

`scan.publish_fresh_sec` 控制发布列表的新鲜度，默认 300 秒。Web 预览允许读旧缓存，正式发布不自动重抓，未通过检查时需先检索。`weekly.py` 定时入口会按需抓取，并在发送前执行同样的完整性检查。

正文默认有效 6 小时（`content.ttl_seconds`），自动补齐窗口默认 14 天（`content.window_days`），`content.batch_limit=0` 表示处理本批全部到期项。未过期正文优先复用，抓取失败不会以旧正文冒充成功。

定时入口会在扫描后复用同一登录上下文补齐提醒天数内的全部到期正文，不受界面正文批次上限截断。即使列表仍新鲜，发现待提醒正文缺失或过期也会重新扫描并补齐，再从缓存读取正文生成文案；正文仍无法取得时才降级为平台提示。

Web 检索后的自动补齐仅针对当前显示日期范围内的缺失/过期正文，每条每轮最多尝试一次，失败后可手动刷新；不会自动遍历历史缓存。预览只读本地，不重新扫描或等待正文抓取完成；正文未就绪时先显示平台提示。

登录、扫描、正文和课程表刷新共用系统文件锁。同一时刻只允许一个平台访问流程，默认最多等待 120 秒；超时明确失败，**不会继续并发抓取**。进程退出后系统释放锁，不按锁文件存在时间强行删除活跃锁。

换账号建议使用新的 `account_scope`（如 `account-b`），重新登录、刷新课程表并全量扫描。默认范围需绑定平台可见身份才能发布；身份冲突会阻断旧缓存复用。课程索引和名单等本地文件也与账号有关，不提供多账号一键切换。

## 定时发布与后台更新

上方「定时发布」默认折叠详细状态，可设置每周日发布时间和未来 1–30 天。保存只安排未来触发，不立即发布，不再单独设置凌晨补推任务。

- 每周任务：`BUCT-Homework-Weekly`，按选择的周日时间首次发布，随后默认每 30 分钟进行补推检查、持续 2 小时；只补发尚未成功的受众，全部成功则跳过。面板将首次时刻与后续补推检查分开标注，下次检查时间不等于下次一定发送消息。
- 旧版独立任务 `BUCT-Homework-Catchup` 已退出默认方案：主任务本身已有错过补跑和后续补推检查，不再另建周日 00:05 任务。CLI 脚本仅保留旧部署兼容；设置面板会停用已有旧任务，不重新创建。未注册或停用的旧任务不显示在状态面板。
- 取消定时停用主任务，并兼容停用仍存在的旧版额外任务，保留历史，不强行终止正在运行的任务。停用后显示「已停用，不会自动运行」，不显示旧下次时间。
- 仅管理固定名称且指向本项目的任务。旧任务权限不足时请求原生 Windows 授权；取消授权、超时或失败会明确显示未保存。

任务使用当前用户交互会话，需要电脑开机、用户登录且网络可用。错过触发后的补跑受 Windows 任务调度和脚本时间判断约束，不能保证关机期间发送。面板只读显示系统状态和最近自动发送记录，不把演练、去重或部分失败当成新的发送成功；实际开关和下次时间以面板实时查询为准。

实际定时执行前后默认各显示一次 Windows 本机通知：开始时说明检索、补齐正文、发布及暂缓操作，结束时显示流程结果和用时。通知独立运行，不需要点确认，不进入群消息；演练、`none` 渠道及当天已发而跳过时不显示。可通过 `task_local_notice=false` 关闭。正常估计约 30–90 秒，登录恢复、网络或图片发送可能更久；这不是发送时限。期间可查看本地列表与预览、正常使用电脑，暂缓手动访问北化在线、再次检索/刷新、修改名单规则及重复发布。正文仍获取失败时保留平台提示，不将“流程完成”当作所有正文完整的保证。

底部「后台版本」比较运行代码与磁盘代码。点击「更新后台」只加载本地已保存代码，不执行 Git 拉取。任务运行/排队时拒绝更新，更新后自动重连并刷新页面，保留手动添加草稿和日期筛选；其他编辑弹窗需先完成或关闭。连接超时会提示重新打开控制台。

## 告警与排错

告警与作业提醒分开配置。默认 `alert.channel=local`，以本机通知和文件记录报告抓取、发送或陈旧问题；默认禁止向班级群发技术告警。同类告警有冷却时间，详见配置示例 `alert` 段。

| 问题 | 处理 |
| --- | --- |
| 登录过期 | 手动检索遇到明确过期会自动续登并重试一次；失败时运行 `login.bat`，处理验证码 |
| 缓存不能发布 | 检查覆盖提示，重新检索；个别课程失败可重试该课程 |
| 正文过期或失败 | 刷新正文；标题和截止仍保留，不发送旧正文摘录 |
| 页面新、后台旧或保存接口不存在 | 使用底部「更新后台」，必要时关闭后重新打开控制台 |
| 计划任务拒绝访问 | 在设置/取消时完成 Windows 授权；取消授权不会保存 |
| 启动失败或拒绝连接 | 查看 `data/server_console.log`、`data/server_error.log`；确认解释器和端口 |
| 图片无法裁剪 | 安装 Pillow 后刷新正文；超限、坏图或不可安全解码的图片会禁用裁剪 |

双击 `.bat` 的 Windows 安全警告需区分来源：下载标记和文件低完整性标签不是一回事。可先运行 `python data/fix_integrity.py --list` 只读检查；修复操作的适用范围见该脚本帮助，不建议无差别改系统权限。

## 命令行与配置

在项目根目录、使用已安装依赖的 Python 执行：

```powershell
python data/hub.py list                         # 只读本地列表
python data/hub.py list --fetch                 # 抓取完整课程列表
python data/hub.py list --all                   # 本地平台列表含过期条目
python data/hub.py publish --no-send            # 本地预览，不发送
python data/weekly.py --no-send                 # 定时链路演练，可能联网抓取
python data/task_run.py --dry-run               # 任务执行链路演练，可能联网抓取
python data/task_register.py --query            # 查询默认每周任务
python data/task_register.py --catchup --query  # 查询默认补推任务
```

两个演练入口失败时也不发送告警。CLI 仍保留旧 `--pool` 首页池模式兼容历史用法，不提供默认完整课程保证；日常使用控制台默认模式。

主要配置集中在 `data/config.json`：渠道与 `personal`、`alert`、`account_scope`、`cache`、`content`、`scan`。具体字段及默认值以 [配置示例](data/config.example.json) 为准。CLI 注册、删除、立即运行任务属于真实系统操作，优先使用 Web 面板设置，不把 `--run-now` 当作只读检查。
