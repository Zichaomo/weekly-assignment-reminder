# 开发维护

本文描述当前代码结构与维护方式。日常操作见 [README](../README.md)，验证范围见 [验收记录](验收记录.md)。执行代理遵循本机私有的 AGENTS.md，默认由主助手单模型完成，不自动委派。

## 主要数据链路

1. 冷打开通过 `GET /api/list` 读取本地缓存，改变日期窗口也不产生平台任务。
2. `fetch` 任务扫描全部未拉黑课程，作业与测试分别记覆盖和错误。按课程提交结果，失败课程旧条目保留供查看。
3. 前端在成功检索后按需提交正文任务；正文独立于列表，缓存有效时复用。
4. `preview` 使用本地缓存，可展示过期或不完整快照。Web `publish` 要求缓存通过完整性、新鲜度及账号检查；不通过时拒绝发送。
5. `weekly.py` 定时入口按需复用新鲜缓存或抓取，正式发送前再次检查覆盖。Web 与定时共享受众拆分、规则和文案格式。

平台条目的提交状态由 `cache_store.normalize_submission` 统一计算，单课持久化、旧缓存读取及抓取 JSON 使用相同规则。结果链接代表已有提交记录，提交或开始入口用于识别待完成条目，缺少证据时保持未知。状态仅供本人查看，班级提醒继续按截止日期筛选。

登录、会话检查与抓取统一复用 `scrape.page_authenticated()`。页面证据需来自北化在线，门户页面和单独票据均不足以确认平台登录。会话检查通过 SSO 入口执行 12 秒有界等待，文件或验证异常返回需登录并关闭检查浏览器；保存新会话前再次核验页面。

课程导航的 `_budget_ms` 同时限制剩余课程预算、调用点上限及 scan.step_timeout_sec。默认步骤上限 12 秒，课程总预算 90 秒。超时表示抓取失败并保留旧缓存，不能用缩短等待后的部分结果宣称完整刷新成功。

正文每次从当前内容计算，不信任旧摘要。人工确认与裁剪绑定 `source_version`、账号范围和身份代次；正文变化、认证失效或账号冲突不会自动恢复旧决定。有效裁剪会替代同一原图的发送资产；无裁剪则使用原图。`save_view` 在事务内校验并生成内容寻址 PNG，区域保存 `delivery_asset_id`；已有旧视图可在生成清单时补齐资产。原图保持不变，裁剪像素基于方向校正后的原图，用归一化 xyxy 的左上向下取整、右下向上取整映射。发送清单含视图 revision，旧清单在裁剪变化后拒绝发送；去重键使用有序图片哈希与实际文案，不因相同裁剪重复保存而失效。

## 主要 HTTP 接口

这些接口服务于本机控制台，不应直接暴露到公网。平台任务仍串行执行；`preview` 走独立本地线程队列，避免自动补正文阻塞本地排版。任务登记和后台更新的忙碌保护仍生效。

| 路径 | 方法与用途 |
| --- | --- |
| `/api/config`、`/api/cache` | GET：公开渠道名及缓存/覆盖状态，不返回 webhook |
| `/api/setup` | GET 本地部署状态，POST 带 expected_revision 完成指引 |
| `/api/settings/account`、`/api/settings/wecom` | GET 账号和地址配置状态，POST 带 expected_revision 保存、清除或显式导入 Edge 凭据 |
| `/api/list` | GET：本地列表，支持 `days`、`all` / `include_expired` |
| `/api/tasks` | POST 提交 `fetch`、`preview`、`publish`、`content`、`refresh-courses`、`login`、`check-login`，登录参数由后端固定 |
| `/api/tasks/{id}` | GET：任务状态、结果及该任务自身扫描进度 |
| `/api/runs` | GET：当前账号的活动任务和历史记录，含脱敏过程、结果摘要及课程覆盖，支持 limit 与 before 游标分页 |
| `/api/courses`、`/api/blacklist` | GET：课程目录与名单；名单 POST：用户显式修改 |
| `/api/manual` | POST：手动条目操作 |
| `/api/assignments/{key}/content` | GET：当前账号下的缓存正文与摘要 |
| `/api/assignments/{key}/review` | POST：按正文版本确认、忽略正文或恢复自动 |
| `/api/assignments/{key}/view` | POST：保存多区域裁剪与发送资产；expected_version 必填，新界面同时带 expected_view_revision（无保存视图时为 none）；冲突返回 409 |
| `/api/assets/{sha256}`、`/api/views/export` | GET：本地图片与人工视图导出 |
| `/api/course-rules` | GET：有效规则与 revision；POST：带 expected_revision 保存或恢复 |
| `/api/course-rules/samples` | GET：当前账号平台作业样本，不含手动条目与测试 |
| `/api/course-rules/preview` | POST：用草稿规则处理缓存作业或粘贴文字，不保存、不抓取、不发送 |
| `/api/runtime`、`/api/runtime/update` | GET：版本；POST：校验磁盘版本与 PID 后更新本地后台 |
| `/api/schedule` | GET：任务快照；POST：校验 revision、项目归属与忙碌状态后设置/取消 |
| `/api/heartbeat`、`/api/shutdown` | 页面心跳、显式停止后台 |

规则保存、定时修改和后台更新与任务提交共用生命周期锁。更新不能与排队/运行任务竞争。平台访问使用系统文件锁，等待超时抛出 `LockTimeout`，禁止降级为并发访问；Windows 存活检查使用 `process_info`，不要用 `os.kill(pid, 0)` 探测。

## 本地数据与版本管理

| 数据 | 位置 |
| --- | --- |
| 推送/账号/缓存配置 | `data/config.json` |
| 登录会话 | `data/storage_state.json` |
| 登录专用 Edge 浏览器资料 | `data/browser-profile/` |
| 历史本机会话归档 | `.local-state/legacy-session/` |
| 课程索引、统计与三个名单 | `data/courses.json`、相关元数据、`course_blacklist.json`、`test_blacklist.json`、`electives.json` |
| 可编辑课程正文规则 | `data/course_rules.json` |
| 手动作业 | `data/manual.json` |
| 列表、正文、身份、确认与裁剪 | `data/cache/homework.sqlite3` |
| 控制台操作与过程 | 同一 SQLite 内的 `task_registry`、`task_events`，过程默认展示每任务最近 100 行 |
| 原图和展示资产 | `data/cache/assets/` |
| 最近两份文案与图片清单 | `data/last_message*.txt`、`data/last_images*.json` |
| 发送/部分发送/检索/任务/告警台账 | `data/push_log.jsonl`、`push_parts.jsonl`、`fetch_log.jsonl`、`task_log.jsonl`、`alert_log.jsonl` |
| 系统授权请求与结果 | `data/schedule_requests/` |
| 私有验证产物、浏览器截图 | `.deepastra-work/`、`tests/artifacts/` |

这些运行数据不入库。账号密码加密载荷保存在配置内的 school_account，读取接口返回用户名和配置状态，密码与 Webhook 字段按留空保留、显式清除处理。新设置接口校验本机 Host、Origin、JSON 类型及版本，保存与平台锁互斥，以临时文件原子替换配置。登录任务仅记录操作名，子进程输出由后端捕获。课程规则文件位于配置文件旁；测试设置 `HOMEWORK_CONFIG_PATH` 后同时隔离这些设置。缓存可通过 `HOMEWORK_CACHE_DB`、`HOMEWORK_CACHE_ASSETS`、`HOMEWORK_ACCOUNT_SCOPE` 覆盖，平台锁通过 `HOMEWORK_LOCK_PATH` 覆盖。更多参数见 [配置示例](../data/config.example.json) 和 `cache_settings()`。

`account_scope` 只接受英文字母、数字、下划线、点、冒号和连字符。日常换账号通过学校账号面板建立新范围，并重新登录、刷新课程表和全量扫描。维护脚本显式换绑同范围时可使用 `HOMEWORK_ACCOUNT_CHANGE=1`，完成后移除，该操作会使旧扫描和正文失效。课程索引、名单和规则仍是配置旁的本地文件，当前产品提供单账号管理。

## 测试与提交

在仓库根目录运行，解释器需安装 Playwright 和 Pillow；本机 `.bat` 使用的解释器路径见 README。长测试应设置外层超时，建议 Python 全套 120 秒、浏览器 100 秒。

按 AGENTS.md 先编写验收或回归测试并复现问题，再修改实现，最后通过同一组测试及相关已有回归。界面验收使用固定时钟核对真实数据状态、原型结构和视口边界。

```powershell
$env:PYTHONIOENCODING='utf-8'
$projectPython = Join-Path $env:LOCALAPPDATA 'Programs\Python\Python314\python.exe'
& $projectPython -B -m unittest discover -s tests -q
$env:PYTHON=$projectPython
node tests/browser_smoke.js
node tests/browser_v0.js
node tests/browser_v0_acceptance.js
node tests/browser_deadline.js
node tests/browser_run_history.js
node tests/browser_setup.js
node tests/browser_management_menu.js
git diff --check
```

浏览器脚本通过 `tests/browser_runtime.js` 统一选择 Python，默认使用 `%LOCALAPPDATA%\Programs\Python\Python314\python.exe`，`PYTHON` 可指定其他解释器。Node Playwright 默认复用所选 Python 包内的 `driver/package`，`PLAYWRIGHT_PATH` 可覆盖其模块路径。fixture 使用临时数据库、配置、名单、规则及资产，阻止真实平台、群发、后台重启和 Windows 任务写入。只有 fixture 的精确本地 origin 可请求，外部请求数必须为 0。测试日志中的模拟登录和发送成功不代表真实账号操作。

提交前阅读实际 diff，明确暂存源码、测试和文档，不暂存凭据、真实配置、日志、数据库或私有验证产物。`.bat` 当前保持 ASCII 启动输出，避免中文代码页差异。受限 Windows 沙箱可能禁止临时目录或浏览器进程；可在获准环境运行隔离回归，不应把权限错误当成功。
