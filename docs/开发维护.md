# 开发维护

本文描述当前代码结构与维护方式。日常操作见 [README](../README.md)，验证范围见 [验收记录](验收记录.md)。执行代理遵循 [AGENTS.md](../AGENTS.md)，默认由主助手单模型完成，不自动委派。

## 代码结构

| 文件 | 职责 |
| --- | --- |
| `data/server.py` | 本地 HTTP 服务、串行长任务队列、任务去重与进度、生命周期互斥 |
| `data/console.html` | Web 控制台，列表、名单、手动条目、正文、确认与裁剪交互 |
| `data/system_panel.js` | 定时状态与设置、后台版本与更新、重连及草稿恢复 |
| `data/course_rules.js` | 课程规则编辑、草稿试用、保存和恢复 |
| `data/hub.py` | 列表、发布、正文、课程名单等应用入口 |
| `data/scrape.py` | 平台身份检查、课程进入、作业/测试全分页扫描、正文读取 |
| `data/login.py`、`data/edge_cred.py` | 登录恢复与本机保存凭据读取 |
| `data/platform_lock.py` | 跨进程平台访问互斥、进程存活与启动信息检查 |
| `data/cache_store.py` | SQLite、扫描覆盖、账号身份代次、正文/人工确认/裁剪版本及任务登记 |
| `data/content_pipeline.py` | 结构化正文、资产下载、图片校验与本地展示 |
| `data/content_summary.py`、`data/course_rules.py` | 当前正文规则计算、课程规则解析、原子保存及冲突检查 |
| `data/weekly.py` | 日期过滤、受众拆分、统一文案格式与定时发布链路 |
| `data/notify.py`、`data/image_delivery.py` | 通道发送、原图混排与回退、部分重试和去重 |
| `data/manual.py` | 手动条目 CRUD |
| `data/alert.py`、`data/fetch_log.py` | 失败告警与检索台账 |
| `data/task_register.py`、`data/task_run.py`、`data/task_catchup.py` | CLI 任务注册、定时执行、补推判断 |
| `data/task_notice.py` | 独立进程显示定时开始/结束的本机气泡，不阻塞发布，不进入群告警通道 |

| `data/console_runtime.py`、`data/restart_backend.py` | 磁盘/运行版本检测与有界重启 |

`console.bat`、`login.bat` 为当前 Windows 启动入口，`console-legacy.bat` 与 `data/console.ps1` 为旧界面兼容入口。`run_hidden.vbs` 用于隐藏启动后台，`wait_ready.py` 检查服务就绪，`focus_console.py` 负责窗口复用。

## 主要数据链路

1. 冷打开通过 `GET /api/list` 读取本地缓存，改变日期窗口也不产生平台任务。
2. `fetch` 任务扫描全部未拉黑课程，作业与测试分别记覆盖和错误。按课程提交结果，失败课程旧条目保留供查看。
3. 前端在成功检索后按需提交正文任务；正文独立于列表，缓存有效时复用。
4. `preview` 使用本地缓存，可展示过期或不完整快照。Web `publish` 要求缓存通过完整性、新鲜度及账号检查；不通过时拒绝发送。
5. `weekly.py` 定时入口按需复用新鲜缓存或抓取，正式发送前再次检查覆盖。Web 与定时共享受众拆分、规则和文案格式。

正文每次从当前内容计算，不信任旧摘要。人工确认与裁剪绑定 `source_version`、账号范围和身份代次；正文变化、认证失效或账号冲突不会自动恢复旧决定。手动裁剪不改变原图发送清单。

## 主要 HTTP 接口

这些接口服务于本机控制台，不应直接暴露到公网。平台任务仍串行执行；`preview` 走独立本地线程队列，避免自动补正文阻塞本地排版。任务登记和后台更新的忙碌保护仍生效。

| 路径 | 方法与用途 |
| --- | --- |
| `/api/config`、`/api/cache` | GET：公开渠道名及缓存/覆盖状态，不返回 webhook |
| `/api/list` | GET：本地列表，支持 `days`、`all` / `include_expired` |
| `/api/tasks` | POST：提交 `fetch`、`preview`、`publish`、`content`、`refresh-courses` |
| `/api/tasks/{id}` | GET：任务状态、结果及该任务自身扫描进度 |
| `/api/courses`、`/api/blacklist` | GET：课程目录与名单；名单 POST：用户显式修改 |
| `/api/manual` | POST：手动条目操作 |
| `/api/assignments/{key}/content` | GET：当前账号下的缓存正文与摘要 |
| `/api/assignments/{key}/review` | POST：按正文版本确认、忽略正文或恢复自动 |
| `/api/assignments/{key}/view` | POST：保存多区域裁剪与视图；冲突返回 409 |
| `/api/assets/{sha256}`、`/api/views/export` | GET：本地图片与人工视图导出 |
| `/api/course-rules` | GET：有效规则与 revision；POST：带 expected_revision 保存或恢复 |
| `/api/course-rules/samples` | GET：当前账号平台作业样本，不含手动条目与测试 |
| `/api/course-rules/preview` | POST：用草稿规则处理缓存作业或粘贴文字，不保存、不抓取、不发送 |
| `/api/runtime`、`/api/runtime/update` | GET：版本；POST：校验磁盘版本与 PID 后更新本地后台 |
| `/api/schedule` | GET：任务快照；POST：校验 revision、项目归属与忙碌状态后设置/取消 |
| `/api/heartbeat`、`/api/shutdown` | 页面心跳、显式停止后台 |

规则保存、定时修改和后台更新与任务提交共用生命周期锁。更新不能与排队/运行任务竞争。平台访问使用系统文件锁，等待超时抛出 `LockTimeout`，禁止降级为并发访问；Windows 存活检查使用 `process_info`，不要用 `os.kill(pid, 0)` 探测。

## 本地数据与版本管理

| 数据 | 位置 |
| --- | --- |
| 推送/账号/缓存配置 | `data/config.json` |
| 登录会话 | `data/storage_state.json` |
| 课程索引、统计与三个名单 | `data/courses.json`、相关元数据、`course_blacklist.json`、`test_blacklist.json`、`electives.json` |
| 可编辑课程正文规则 | `data/course_rules.json` |
| 手动作业 | `data/manual.json` |
| 列表、正文、身份、确认与裁剪 | `data/cache/homework.sqlite3` |
| 原图和展示资产 | `data/cache/assets/` |
| 最近两份文案与图片清单 | `data/last_message*.txt`、`data/last_images*.json` |
| 发送/部分发送/检索/任务/告警台账 | `data/push_log.jsonl`、`push_parts.jsonl`、`fetch_log.jsonl`、`task_log.jsonl`、`alert_log.jsonl` |
| 系统授权请求与结果 | `data/schedule_requests/` |
| 私有验证产物、浏览器截图 | `.deepastra-work/`、`tests/artifacts/` |

这些运行数据不入库。课程规则文件位于配置文件旁；测试设置 `HOMEWORK_CONFIG_PATH` 后会自动隔离该文件。缓存可通过 `HOMEWORK_CACHE_DB`、`HOMEWORK_CACHE_ASSETS`、`HOMEWORK_ACCOUNT_SCOPE` 覆盖，平台锁通过 `HOMEWORK_LOCK_PATH` 覆盖。更多参数见 [配置示例](../data/config.example.json) 和 `cache_settings()`。

`account_scope` 只接受英文字母、数字、下划线、点、冒号和连字符。多账号操作优先使用新范围，并重新登录、刷新课程表和全量扫描。同范围显式换绑可使用 `HOMEWORK_ACCOUNT_CHANGE=1`，完成后移除；它会使旧扫描和正文失效，不是跳过身份检查的开关。课程索引、名单和规则仍是配置旁的本地文件，不提供完整多账号配置管理。

## 测试与提交

在仓库根目录运行，解释器需安装 Playwright 和 Pillow；本机 `.bat` 使用的解释器路径见 README。长测试应设置外层超时，建议 Python 全套 120 秒、浏览器 100 秒。

```powershell
$env:PYTHONIOENCODING='utf-8'
python -B -m unittest discover -s tests -q
$env:PYTHON=(Get-Command python).Source
node tests/browser_smoke.js
git diff --check
```

浏览器脚本复用系统 Edge，`PLAYWRIGHT_PATH` 可覆盖其 Node Playwright 模块路径。fixture 使用临时数据库、配置、名单、规则及资产，阻止真实平台、群发、后台重启和 Windows 任务写入。只有 fixture 的精确本地 origin 可请求，外部请求数必须为 0。测试日志中的模拟登录和发送成功不代表真实账号操作。

提交前阅读实际 diff，明确暂存源码、测试和文档，不暂存凭据、真实配置、日志、数据库或私有验证产物。`.bat` 当前保持 ASCII 启动输出，避免中文代码页差异。受限 Windows 沙箱可能禁止临时目录或浏览器进程；可在获准环境运行隔离回归，不应把权限错误当成功。

## 文档维护约定

README 维护当前可用功能与操作；本文维护架构、接口和本地数据；验收记录维护实际检查结果和边界。不再向多个文档反复追加会话交接、临时 PID、某一时刻任务开关或“本轮未提交”等易过期状态。历史实现细节通过 Git 追溯，私有原始证据继续留在忽略目录。
