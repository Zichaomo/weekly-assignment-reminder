# v0 第二轮界面验收与接入

历史原型验收文档，验收日期为 2026-11-08，对象为 `ui_v0/` 下第二轮静态前端。下文记录接入前的阶段状态。当前功能及裁剪发送能力见 [README](../README.md)、[开发维护](开发维护.md) 和 [验收记录](验收记录.md)。

## 结论

本轮约定的三组新增界面基本完成：三个课程名单、手动作业表单及确认、图片查看和简化裁剪框。可以作为后续接入的视觉基线。

当前仍为静态演示，不是生产可用控制台。存在图标 CDN 故障阻断课程管理、桌面小高度布局溢出两项已复现问题，接入前需要修正。没有修改原型源码或现有生产代码，也没有访问学校平台、发送消息或修改系统任务。

本地检查时没有发现 ZIP，`ui_v0/` 已是展开后的 9 个文件，共 226170 字节；无法据此验证与原压缩包逐字节一致。所有本地静态资源均可读取，验收前后 9 个源文件的 SHA-256 一致。

## 已复现问题与接入注意事项

### 接入前优先修复

1. **离线/CDN 失败会阻断部分交互。** `js/app.js` 的 `icons()` 无条件调用全局 `lucide`，课程管理在 `renderCourses()` 调图标后才打开。unpkg 被阻断时出现 `lucide is not defined`，课程管理打不开。应把图标本地化，并让图标渲染失败不影响功能；字体也应改为本地资源或可靠回退。
2. **首页窗口高度与滚动边界不稳定。** 1280×800 复测时 `.window` 高 820px，顶部约 118px、底部约 938px，超出视口；浏览器为聚焦控件又会自动滚动，出现顶部被截的状态。1440×900 也记录到文档高度 950px、非零页面滚动。需要调整 `.stage/.window` 的网格尺寸约束和视口高度，保证页面外壳完整、列表/详情内部滚动。不能只用 fullPage 截图判断视口可见性。

### 绑定真实数据时一起处理

- `panels.js` 的编辑、完成、删除都写死了 `MANUAL_SAMPLE` 或“大学英语 · 单元练习”，必须绑定当前选中条目的 `manual_id`，不能拿展示样本当实际 ID。
- 手动科目当前只能从示例课程 select 选择，实际补录需要允许输入平台外科目。
- 手动项仍显示“确认推送内容”按钮，而现有人工正文确认机制针对平台正文，应隐藏或按实际能力重新设计。
- `data.js` 的时间、老师、学分、群名、版本与定时状态全部是演示值；实际接口没有的字段不要虚构。包括图片文字中的“带 * 为选做”等解释，不能当作真实作业规则。
- 名单底部写“下次检索生效”过于笼统。抓取范围与选修受众的生效时机不同，后续以现有后端行为和真实保存结果为准。
- 搜索空结果时旧详情不清空；全量统计与筛选结果需要明确区分。预览仍缺紧急分组和图片，需要复用后端文案与图片清单。
- 多处 `innerHTML` 直接拼接课程、标题、正文；接入真实平台内容前必须安全转义或使用安全 DOM 构造，不能把当前虚构数据的安全性外推到接口输入。
- 原型是全局脚本和顶层常量，保持脚本加载次序，避免和旧控制台脚本重复声明 `$` 等变量。
- 原型未实现未保存表单关闭提醒、完整预览键盘焦点管理；在真实编辑/发布阶段补齐。

## 裁剪图群发送：用户已明确的新需求

用户已明确：无已保存裁剪时使用原图；保存后，后续群提醒应使用裁剪结果，原图保留。保存本身不立即发送。支持后续重新编辑或恢复原图。

**当前后端仍只将裁剪用于本地视图，图片发送使用原图。** README 和开发维护中对此的描述是现有行为，不代表用户希望永远保持该限制。裁剪图群发送不能只靠给新按钮绑定旧 `/view` 接口实现。

后续需要单独实现并验收：真实坐标交互、原图尺寸坐标映射、版本/账号校验、裁剪资产生成与持久化、实际发送图片选择、预览一致性、通道兼容及去重/部分失败重试。不能假定原平台匿名图片链接可以直接表示裁剪结果，也不要擅自引入外部图床。

本次静态裁剪框只作为视觉参考；显示的选区尺寸不是服务端真实裁剪数据。

## 现有 API 接入索引

请求字段及响应结构以 `data/server.py`、`data/hub.py` 和旧控制台实际调用为准；不要重新造一套后端。

| 新界面 | 复用接口 / 对应注意事项 |
| --- | --- |
| 列表与覆盖 | GET `/api/list`、`/api/cache`、`/api/config`；冷打开和日期筛选只读本地 |
| 检索/正文/课程表 | POST `/api/tasks`，op 为 fetch/content/refresh-courses；按 task_id 查询 GET `/api/tasks/{id}` |
| 课程目录与名单 | GET `/api/courses`、GET/POST `/api/blacklist`；kind 是 course/test/elective，原型 quiz 要映射为 test；加入 action=apply，移出 action=remove，按 lids 传真实标识 |
| 手动操作 | POST `/api/manual`；action=add/edit/done/rm/clean；表单日期时间合成 deadline；编辑/完成/删除使用真实 manual_id |
| 正文与人工确认 | GET `/api/assignments/{key}/content`、POST `/api/assignments/{key}/review`；使用真实 item_key 和版本，处理 409 并保留草稿 |
| 原有裁剪视图 | POST `/api/assignments/{key}/view`；仅视图存储，仍需补裁剪图发布链路 |
| 本地图片/备份 | GET `/api/assets/{sha256}`、`/api/views/export`；替换固定 homework.png |
| 预览与发布 | POST `/api/tasks`，op=preview/publish；后端校验身份、覆盖和新鲜度；业务结果不能只看 HTTP 200 |
| 规则 | GET/POST `/api/course-rules` 及 samples/preview；保留 revision 和忙碌保护 |
| 定时/后台 | GET/POST `/api/schedule`、GET `/api/runtime`、POST `/api/runtime/update`；保留项目归属、revision、忙碌和更新保护 |
| 平台打开/生命周期 | POST `/api/open`、`/api/heartbeat`、`/api/shutdown`；新前端不可漏掉现有生命周期约定 |

列表模型也要适配：后端 source 使用“平台/手动”、kind 使用 homework/test；不是原型 platform/quiz/manual 的一一字段替换。真实条目以 item_key 等稳定键识别，不使用示例 1—6 编号或标题作主键。

## 建议下一会话的工作顺序

1. 阅读本文件、AGENTS、README、开发维护及实际源码。保护当前已有改动，保留原型视觉基线，不立即覆盖生产入口。
2. 先处理本地图标/字体与窗口尺寸问题，确定多文件静态资源如何由现有 Python 服务提供；不必迁移 React。
3. 接列表/状态/任务轮询，替换演示数据、日期和状态，保持原列表完整性与提交不影响班级提醒原则。
4. 接三个名单和手动条目，成功后再刷新真实界面；失败不假报保存成功。之后接正文、统一预览及剩余管理入口。
5. 单独完成并验收“保存裁剪后发送裁剪图”新增业务，处理预览、发送、版本和重试的一致性。
6. 使用隔离 fixture、临时配置/缓存和浏览器回归验证后，再整合生产入口。实发验证仅允许测试群；本轮默认本地不发送预览，不改变既有日常定时目标。
