# 每周作业提醒 · v0 视觉探索任务书

历史视觉探索任务书，整理日期为 2026-10-30。本文保留设计需求及虚构样本，当前控制台使用说明见 [README](../README.md)。

## 先读这段：我希望你完成什么

请为一个已经能用的中文本地工具「每周作业提醒」设计新版前端。目标是探索更好的布局、视觉和交互，并交付能运行、能导出源码的前端原型，之后由本地开发助手接入现有 Python 后端。

请直接制作可交互页面，不要只回复设计建议。以桌面作业工作台为主，把作业清单、正文阅读和双群发布预览做完整。其他管理功能可以使用同一应用内的页面、抽屉或弹窗，但需要有入口及可演示的操作。使用本文的虚构数据，不连接学校平台、不发送消息、不修改 Windows 任务。

这是已有产品的界面重设计。请保留下面的业务能力和操作含义，重新组织页面；不要自行改造成带注册、付费、团队空间的 SaaS，也不要重写后端。

## 1. 产品背景与实际使用

- 用户：北京化工大学学生，主要由整理作业、向班级发提醒的人操作。
- 来源：学校「北化在线」THEOL 平台的课程作业、在线测试，以及手动补录的任务。
- 使用环境：Windows 本地 Python 服务，通过 Microsoft Edge 应用窗口打开，主要使用鼠标和键盘。
- 核心流程：查看本地作业 → 检索最新数据 → 阅读正文、必要时调整规则或确认内容 → 核对班级群和个人群预览 → 发布；也可设置每周日自动发布。
- 核心问题：不能漏提醒；截止时间要清晰；图片、正文和推送内容方便核对；不要为了看作业频繁翻页和滚动。

当前前端是 HTML、CSS、原生 JavaScript，后端是 Python 本地 HTTP 服务和 SQLite 缓存。当前生产入口是 `http://127.0.0.1:8277`，不是部署在 Vercel 上的在线应用。本次原型必须独立运行，不依赖访问这个地址。

## 2. 现有界面与改造目标

当前页面由上到下排列：报头、定时发布、检索与发布操作栏、手动添加表单、作业表格、推送预览/运行日志、后台版本。名单、正文确认、裁剪、定时设置及课程正文规则通过弹窗编辑。

现有界面使用米白底、深色字、橙色强调、细分隔线和带书写感的中文报头。可延续它的纸面感，但可以重新设计布局，不必照搬旧组件。

需要改善：

1. 首屏尽快看到近期作业，而不是先看大段系统状态和表单。
2. 查看正文和图片时，仍能快速切换作业，不让表格被长正文撑开。
3. 清楚区分「学校提交状态」「数据状态」「正文处理状态」「提醒发送结果」。不要合并成一个含义不清的状态徽章。
4. 班级和个人预览容易对照，能看出选修课差异以及为什么暂时不能发布。
5. 常用操作就近放置，低频管理入口收纳有序；错误提示给出下一步。

## 3. 视觉方向

优先制作一套精致、克制、适合中文密集信息的浅色桌面工作台。

| 项目 | 建议 |
| --- | --- |
| 气质 | 安静、清楚、有少量编辑排版感；像每天会打开的工具 |
| 颜色起点 | 页面 `#F0F0EE`、内容面 `#F9F8F5`、主字色 `#1F1E1C`、边线 `#DBDAD3`、强调橙 `#F5572F`；允许微调以保证对比度 |
| 状态色 | 橙用于临近截止/提醒，红用于失败/逾期，绿用于有效/成功；同时配文字或图标 |
| 字体 | 中文无衬线优先；标题可少量使用有书写感的字体。没有原字体文件时用可用字体回退，不依赖本机字体路径 |
| 密度 | 正文约 14–16px，辅助信息不宜过小；用对齐、字重和留白建立层级 |
| 组件 | 轻边框、有限圆角、少量阴影，图标风格统一；表格/列表保持足够的信息密度 |
| 屏幕 | 优先 1440×900，同时检查 1280×800、1920×1080；窄屏可改为列表进入详情的单栏流程 |

避免首屏大幅宣传标题、装饰插画、大面积渐变、过量大卡片和无业务意义的图表。深色模式可以后续再做。本次重点是主流程的可读性与完整性。

## 4. 建议的信息架构（这是新设计建议，不是现有页面结构）

建议左侧导航包含「作业总览」「发布预览」「课程与规则」「运行与设置」。你可以合并导航，但不要丢失功能。

### A. 作业总览：第一优先级

- 顶栏：工具名称、日期、小型定时摘要、主操作「检索北化在线」、次操作「添加作业」「预览提醒」。
- 近期概览：今天截止、近两天截止、本周作业。统计来自当前数据，明确范围，避免重复计算造成误解。待处理正文可作为辅助数字。
- 筛选：未来 1–30 天；显示已过期平台作业；抓在线测试（属于下次检索选项，不只是列表过滤）。
- 可新增课程/标题搜索和课程筛选，作为本地交互，不触发联网检索。
- 列表：课程、标题、作业/测试/手动/选修标记、截止日期时间、剩余时间、必要的数据/正文提示。平台来源与手动来源可用紧凑标记呈现。
- 默认按截止时间排序；今天、明天、稍后等分组可用于改善阅读。
- 选中条目后在右侧显示详情；列表可以继续选择其他条目。小屏切为全宽详情并支持返回。
- 平台条目保留「在北化在线打开」「查看/刷新正文」；仅手动条目提供编辑、完成、删除。
- 手动添加不需要一直占据整行：可改为抽屉或弹窗，字段为科目、标题、截止、备注。日期输入友好，保留用户草稿。
- 顶部或列表附近显示数据更新时间、扫描覆盖和可发布状态；细节可展开。扫描期间保留旧列表可读，按课程显示实际进度。

### B. 作业详情与图片：第一优先级

- 顶部显示课程、标题、截止、来源；学校提交状态仅作辅助信息。
- 优先显示真正的作业要求：题号、章节、页码或任务摘要；完整原文折叠展开。
- 支持文字、段落、列表、表格、图片、附件入口；长课程名和长标题可以换行，不遮挡截止信息。
- 正文状态至少区分：可用、尚未缓存、刷新中、已过期、失败、待确认、人工确认已失效。
- 无可靠摘要时提示到平台查看，仍保留标题和截止。不要求用户每天逐条确认所有未知正文。
- 人工确认：编辑最终推送正文、确认不推正文、恢复自动识别；保存成功/失败有反馈，版本冲突保留草稿。
- 图片：缩略图、原图放大、多个裁剪区域、区域预览、撤销/恢复、保存裁剪。演示图片使用本地生成的虚构习题页或自带示例资产，禁止使用真实课程材料。
- 明确说明「裁剪仅用于本地查看，群消息仍按规则发送原图」。
- 正文很长、多图、图片加载失败时，页面仍可操作。

### C. 发布预览：第一优先级

- 两份预览分别标为「班级群」和「个人群 · 含选修课」，宽屏并排，窄屏标签切换。
- 两份文案各显示条目数、数据时间/有效性，以及图片在作业中的相对位置。
- 消息顺序：作业标题与截止 → 本项有效正文/原图 → 下一项。图片不能全部堆在末尾。
- 文案按「近两天截止」「本周稍后」分组，无条目分组不显示。没有待交条目时显示无作业提示。
- 提供「生成预览」「复制」和显眼但克制的「提前发布」。真实接入时发布前需要二次确认受众与内容。
- 旧数据也能预览，但必须说明无法正式发布的原因及补救方式。
- 演示完整成功、班级成功/个人失败、图片部分失败等结果；仅失败部分可以重试的含义要清楚，不能把部分成功画成全部成功。
- 本次所有发布按钮都只做 mock 演示，明确显示「演示模式，未发送」。

### D. 课程与规则

三个名单可以做成标签页，但含义必须分开：

| 名单 | 含义 |
| --- | --- |
| 课程黑名单 | 整门课作业和测试都不抓取 |
| 测试黑名单 | 该课作业照抓，只跳过测试 |
| 选修课名单 | 作业、测试照抓；排除班级提醒，保留个人提醒 |

- 名单支持候选/已选、搜索、加入和移出、操作确认，以及刷新课程表入口。选修课可按课程编号或名称片段添加。
- 课程正文规则使用「规则列表 + 编辑区 + 试用结果」布局。支持新增、编辑、恢复内置默认、删除自定义规则。
- 匹配方式：名称完全相同/课程名以此开头。精确匹配优先，前缀匹配时采用名称最长的规则。
- 五种策略：自动识别题号与任务、仅提示查看北化在线、去除通用提交说明、保留全部纯文字、发送正文原图。
- 群消息正文最多显示 1–20 个非空行，默认 3 行；超出显示「……（详情参见北化在线）」。这是消息摘要行数，不限制详情页全文。
- 用已缓存作业或粘贴文字试用草稿，不保存试用正文、不联网、不发送；编辑草稿后旧试用结果要标为需重新预览。
- 保存规则后后续预览立即使用新规则，无需重新抓取；已发送消息不变。

内置规则可用以下公开课程名称演示，任务和时间全部虚构：大学物理实验→仅提示；普通物理→去套话；嵌入式系统创新应用与实践→全部纯文字；复变函数→原图；其他→自动。

### E. 运行与设置

- 定时设置：固定每周日、时间、未来 1–30 天、错过后的补推检查。每次打开设置时补推默认勾选。
- 保存只安排未来执行，不立即发送；取消同时停用每周任务和补推，不强行中止已运行任务。
- 首页仅保留简短定时摘要和设置入口；下次时间、上次运行结果、两个受众最近自动发送成功记录放在详情中。
- 停用后显示「已停用，不会自动运行」，不显示旧的下次时间。状态查询失败时显示未知，不冒充已停用。
- Windows 授权被取消或操作失败时显示「未保存」，保留用户输入；演示中只模拟，不触发系统授权。
- 运行任务区分排队、执行、部分失败、完成、失败；日志可展开，技术明细不要挤进日常作业清单。
- 后台版本：运行版本与本地版本，检查、更新、重连状态。这里的更新是加载本地代码，不是 Git 拉取或在线升级。
- 任务运行/排队时，不允许保存规则、修改定时或更新后台；解释禁用原因。浏览作业仍保持可用。
- 更新时保存手动录入草稿和日期筛选；其他编辑需先完成/关闭。保留停止服务、导出裁剪备份入口。

## 5. 不得改变的业务规则

1. 提醒面向全班，以截止时间筛选，不能因为当前用户已提交而隐藏作业或排除提醒。平台条目不设计成可点击勾选完成的个人待办。
2. 手动条目可标完成，完成后退出待办提醒；平台条目只读，原文和截止不能在这里任意改写。
3. 所有未拉黑课程都检查，不能依赖学校首页待提交池，也不能把课程筛选误变成默认缩小扫描范围。
4. 列表筛选包含过期项，不代表群推送包含过期项；推送仍按未来天数计算。手动条目的现有列表范围和平台不同，接入时以原接口返回结果为准。
5. 打开页面、切换日期范围和生成 Web 预览只读本地缓存，不自动抓取平台。正式 Web 发布遇到不完整、不新鲜或身份失效的缓存会拒绝，需用户先检索。
6. 课程扫描失败要保留旧列表供阅读，同时明确缺失范围；不能把旧条目当成本次完整扫描。
7. 扫描、登录、正文和课程表刷新串行访问平台；不能用前端并发任务绕过后端互斥。正文补齐期间不阻塞本地阅读。
8. 正文缺失、过期、失败或账号身份失效时不能引用旧正文；可靠标题和截止的提醒逻辑仍保留。
9. 人工确认绑定账号和原文版本；原文变化后失效，不能静默沿用。保存遇到 409 应保留草稿，不覆盖新版本。
10. 人工确认优先于自动文字/原图策略；「仅提示查看北化在线」策略始终生效。课程作业正文规则不套用到手动条目或在线测试。
11. 原图策略需要原图就绪；文字策略遇复杂图文时有保守回退。前端显示后端处理结果，不在浏览器另写一套摘要或判定算法。
12. 班级群和个人群独立计数、独立发送与记账。个人渠道未配置时不回退发到班级群。运行完成、演练、去重、部分成功均不等于本次全部发送成功。
13. 定时依赖本机开机、登录和网络；不能宣传关机后云端仍能自动发送。

## 6. 必须可以演示的状态

请用一个收纳在开发演示区域的场景切换器呈现，不占正常页面主操作区。允许模拟异步等待，但不能随机制造结果。

| 场景 | 应看到的行为 |
| --- | --- |
| 首次打开，无缓存 | 清楚的空状态和检索入口，无虚假的成功统计 |
| 正常、有新鲜完整缓存 | 默认首页，选中作业可看详情和预览 |

| 缓存过期或身份失效 | 明确原因与重新检索/处理登录入口，不展示发布成功 |
| 正文过期、失败或原图缺失 | 有占位、失败反馈和刷新入口，列表不塌陷 |
| 人工确认/规则保存冲突 | 提示内容已更新，保留用户草稿 |
| 定时停用、未知、保存失败 | 显示三种不同状态，失败不改成保存成功 |
| 双受众部分发送失败 | 演示班级成功、个人失败，以及文字成功/图片失败的差异 |
| 后台更新与连接中断 | 显示重连、恢复草稿、超时后的处理提示 |

## 8. 前端实现与后续接入

本阶段可使用 React、TypeScript、Tailwind 和 shadcn/ui。如果 v0 默认使用 Next.js 可以保留，但界面和交互应能接入现有本地服务；不要依赖 Server Actions、新数据库或 Vercel 云服务承载核心业务。

- 业务数据统一经过服务适配层，组件不直接散落调用 `fetch`。
- 提供明确的 mock 实现，默认启用；前端 ViewModel 与真实 API 数据分开，注明映射位置。下面的接口仅作后续接入索引，不是完整字段契约。
- 原型阶段只接 mock，不实现真实发布、学校登录、计划任务或后台重启。状态切换器的状态不应伪装为真实接口返回。
- 组件建议拆为 AppShell、AssignmentList、AssignmentDetail、PublishPreview、CourseLists、CourseRuleEditor、ScheduleSettings、RuntimeStatus；避免单文件堆积全部状态和布局。
- 后续生产请求使用可配置的同源 `/api` 或开发代理；不要假设云端预览能访问用户电脑的 localhost，不开启公网后端，不擅自修改 CORS/认证规则。
- 所有主流程不依赖远程字体、外部图片、分析 SDK 或在线模型；缺少网络时原型仍可展示本地资产。

现有接口索引（已实现于本地后端；这次不要求 v0 实现或调用）：

| 接口 | 用途 |
| --- | --- |
| `GET /api/config`、`GET /api/cache` | 公开渠道名、缓存及覆盖状态，不提供 webhook |
| `GET /api/list?days=7&include_expired=0` | 只读本地列表 |
| `POST /api/tasks`、`GET /api/tasks/{id}` | 提交任务、独立轮询状态及进度；操作含 fetch/preview/publish/content/refresh-courses |
| `GET /api/assignments/{key}/content` | 正文、摘要、原图和版本 |
| `POST /api/assignments/{key}/review`、`POST /api/assignments/{key}/view` | 人工确认、裁剪视图；版本冲突返回 409 |
| `GET /api/assets/{sha256}`、`GET /api/views/export` | 本地图片、裁剪备份导出 |
| `POST /api/manual` | 添加、编辑、完成、删除、清理手动条目 |
| `GET /api/courses`、`GET/POST /api/blacklist` | 课程索引、三个名单 |
| `GET/POST /api/course-rules` | 规则及 revision；保存携带 expected_revision |
| `GET /api/course-rules/samples`、`POST /api/course-rules/preview` | 本地规则样本、草稿试用 |
| `GET/POST /api/schedule` | 定时查询、设置、取消；修改校验 revision 和忙碌状态 |
| `GET /api/runtime`、`POST /api/runtime/update` | 后台版本、更新；校验版本和 PID |
| `POST /api/open`、`POST /api/heartbeat`、`POST /api/shutdown` | 安全打开平台/附件链接、页面心跳、停止服务 |

示例字段映射方向：平台行已有 `item_key`、`course`、`title`、`deadline`、`source`、`kind`、`submit_state`、`content_status`、`content_stale`、`source_version`；手动行有 `manual_id`。选修、发布资格与其他状态应由现有后端结果/适配层组合，不能假定全在同一行结构中。

接入时 URL 中的作业 key 必须编码，保存时沿用版本字段。任务可能为 queued/running/done/partial/error；终态和业务结果均需检查，HTTP 200 不自动代表群发送成功。实际响应结构与参数以本地源码为准。
